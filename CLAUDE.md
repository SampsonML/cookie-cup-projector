## Repository state

The repo holds a static-site projector for The Cookie Cup (14-team AFL Fantasy keeper league) plus the Python pipeline that feeds it.

**Source of truth for player stats**: the latest `data/The_Cookie_Cup_players_*.csv` (weekly export from keeperfantasy). These files use the league's actual scoring (standard AFL Fantasy Classic) and contain current-season form windows (L5/L3/L1), season averages (avgPts), and keeperfantasy's own per-game projection (projAvg). All projections and per-player stats on the site come from this CSV — the older xlsx files are retained in `data/` for archival but are not parsed.

- `data/The_Cookie_Cup_players_<YYYYMMDD>_<HHMM>.csv` — weekly snapshot. `parse_stats.py` always picks the most-recently-dated one.
- `data/afl-fantasy-2026.xlsx` (+ 2023/2024/2025 xlsx) — historical / archival only; not consumed by the pipeline.
- `scripts/` — Python pipeline:
  - `parse_stats.py` — reads the latest weekly CSV, writes `docs/data/players.json`.
  - `probe_keeperfantasy.py` — diagnostic; dumps HTML + extracted Stimulus/React data blobs to `scripts/.cache/probe/` (kept for future schema changes).
  - `fetch_rosters.py` — scrapes the 14-team keeperfantasy league into `docs/data/rosters.json`. Reads each team page `/afl/<league>/<1..14>`, extracts the `data-lineup-lineup-value` Stimulus JSON, resolves each player against `players.json` by name + AFL team (with nickname fuzzy matching: Brad↔Bradley, Ollie↔Oliver, Matty↔Matt, Lachie↔Lachlan, etc.). Also reads `/matchup` for the AFL team id→abbr map and the league's scoring formula, the `/ladder` page for standings, and iterates `/_matchups?round=N` for the full-season fixture list.
  - `fetch_round_scores.py` — run **after** `fetch_rosters.py` (it reads `rosters.json` standings to know which rounds are complete = `min(played)`). For every completed round it scrapes the 7 per-matchup detail pages `/afl/<league>/matchup?round=R&m=M`, pulls the Symfony UX React `staticData` blob (`pointsByPlayerId` = actual points each player scored, `team1`/`team2` lineups with `type` starter/emg), and writes per-round actual scores to `docs/data/round_scores.json`. Powers the MVP/LVP tabs.
  - `config.json` (gitignored) — `{ "league_id", "team_url_hint" }`.
  - `cookie.txt` (gitignored) — raw `Cookie` request-header value. Get it from DevTools → Network → any keeperfantasy request → Request Headers → Cookie.
- `docs/` — static SPA (vanilla JS, no build step). Deployed via GitHub Pages from `main`/`/docs` to https://sampsonml.github.io/cookie-cup-projector/.
  - `index.html`, `styles.css`, `app.js`
  - `data/players.json`, `data/rosters.json`, `data/round_scores.json` (all generated by the pipeline).
  - `imgs/` — `cookie_logo.jpg` (header logo, flanks the title).
- `analysis.py`, `draft_analysis.py`, `plots/` — pre-existing exploratory analysis; gitignored.

### Run

Weekly refresh (order matters — `fetch_round_scores.py` reads `rosters.json`):
```bash
python3 scripts/parse_stats.py && python3 scripts/fetch_rosters.py && python3 scripts/fetch_round_scores.py
```

Initial setup:
```bash
pip install -r requirements.txt
cp scripts/config.example.json scripts/config.json
# then paste raw Cookie header value into scripts/cookie.txt (one line, no quoting)
python3 -m http.server 8765 --directory docs    # local preview
```

### rosters.json shape

Produced by `fetch_rosters.py`. Each team entry:

```json
{
  "id": "14",
  "name": "Naughty Dog Entertainment",
  "formation": { "starters": [...], "emgs": [...], "bonus": [...] },
  "roster": [
    {
      "kf_id": 523, "name": "Bailey Dale", "team_afl": "WBD",
      "positions": ["DEF"], "selected_pos": "DEF",
      "type": "starter", "starting": true,
      "playing_status": 1, "injured": false, "injury_desc": null,
      "cd_id": "CD_I...", "match_quality": "ok"
    }
  ]
}
```

Top-level keys include `has_captains`, `scoring_formula`, `round` (the keeperfantasy `/matchup` round — **lags**: it stays on a round until the next opens, so a finished round still reports itself as current), `total_rounds`, `standings` (parsed `/ladder` rows: `team_id`, `played`, `w/l/d`, `pf/pa`, `pts`, `rank`, …), `fixtures` (every round's 7 matchups with `home_score`/`away_score`, 0/0 if unplayed), `afl_team_map`, `sport_fixtures` (AFL games for the round, with team abbreviations).

### round_scores.json shape

Produced by `fetch_round_scores.py`. `{ generated_at, league_id, completed_through, rounds: [...] }` where each round is:

```json
{
  "round": 9,
  "matchups": [
    {
      "m": 1,
      "team1": { "league_team_id": 1, "name": "Jags to riches", "score": 865,
                 "starters": [ { "id": 3214, "name": "Hugh McCluggage",
                                 "pos": "MID", "points": 93 } ] },
      "team2": { "league_team_id": 10, "name": "GuldenEye", "score": 892, "starters": [...] }
    }
  ]
}
```

`score` is the sum of the 12 `starters[*].points` (the players whose `type` was `starter` that round — actual fantasy points that counted). `id` matches `rosters.json` `kf_id`.

### Projection model

In `docs/app.js`, `project(p, mode)` blends the weekly CSV's signals (all in Cookie Cup scoring, i.e. AFL Fantasy Classic):
- `blend` (default): `0.35·L5 + 0.15·L3 + 0.30·avgPts + 0.20·projAvg`, normalized by available signals. avgPts is the 2026 season average; projAvg is keeperfantasy's own per-game projection.
- `l5`: last-5 average only (fallback chain: L5 → L3 → avgPts → projAvg).
- `season`: season average only (avgPts → L5 → projAvg).
- `kf`: keeperfantasy's projAvg only (projAvg → L5 → avgPts).

**Team projection always uses a full 12-man lineup** (this league: 3 DEF + 5 MID + 1 RUC + 3 FWD). `teamProjection(team)` in `app.js` replaces every out starter with the best available non-starter on the same roster — preferring one eligible for the vacated `selected_pos`, otherwise the best remaining sub of any position, so the count is always 12. A starter is "out" per `isOut(entry)` if user-excluded, `playing_status === 9`, `injured`, or has no projectable stats. (Note `isAvailable` is a separate, display-only predicate used by the lineup drawer that only gates on `playing_status === 9`.) The league has `numCaptains: 0` so no captain bonus is applied.

### SPA tabs (`docs/app.js` / `index.html`)

Tab order: Matchups, Round Projections, Predicted Final, Premiership Hope, **Race2Spoon**, Finish Odds, **MVP**, **LVP**, Players.

- **Matchups** — uses `displayRound()` (next round after the fewest games any team has played, from `standings`) rather than the lagging `rosters.round`, so it advances to the upcoming round as soon as one finishes; unplayed fixtures show projected team scores.
- **Predicted Final / Premiership Hope / Race2Spoon / Finish Odds** — all read the single cached `runMCMC()` result. Race2Spoon mirrors Premiership Hope but ranks by P(finish last) = tail of each team's rank distribution.
- **MVP / LVP** — share `renderShareBoard(kind)` over `computeWinShares()` (from `round_scores.json`). Each has a "Method" menu (`mvpMethod`/`lvpMethod`, persisted): **Actual (Shapley)** = exact Shapley value of each player toward their team's real results (per game, replacing a player with the league-wide position-mean; per-game credits sum to `v(real lineup) − v(all-replacement)`); **Projected** = Gaussian win-probability-added (σ=`MVP_SIGMA_GAME`=100). LVP loss share = −(win share), ranked most-negative first.

### MCMC engine (`runMCMC`)

10,000 sims, σ=120 Gaussian noise per team per game (`MCMC_SIMS`/`MCMC_SIGMA`), cached by `(model, excluded set)`. Baseline from `standings`; it **bakes in only completed _prior_ rounds** the ladder hasn't yet reflected (`f.round < rosters.round` with scores, not already in standings) — the live round and everything after is **simulated**, never frozen at partial scores, so current points always match the official ladder. Produces per-team expected W/L/D/PF/PA/PTS, P(finals), P(premiership), and full rank distribution. Finals bracket: 3v6 & 4v5 → 1 v winner(4v5), 2 v winner(3v6) → GF.

### Weekly CSV schema

`data/The_Cookie_Cup_players_<date>.csv` — 26 columns: `name, team, position, owner, age, careerGames, seasons, adp, ownedPct, projAvg, avgPts, totalPts, L5, L3, L1, games, TOG%, kicks, handballs, marks, hitouts, tackles, freesFor, freesAgainst, goals, behinds`. The per-game raw stats (kicks/handballs/marks/etc.) are season averages and can be used to recompute scores under alternative scoring formulas. `owner` is the keeper league team that currently rosters the player.

## Repository state

The repo holds a static-site projector for The Cookie Cup (14-team AFL Fantasy keeper league) plus the Python pipeline that feeds it.

**Source of truth for player stats**: the latest `data/The_Cookie_Cup_players_*.csv` (weekly export from keeperfantasy). These files use the league's actual scoring (standard AFL Fantasy Classic) and contain current-season form windows (L5/L3/L1), season averages (avgPts), and keeperfantasy's own per-game projection (projAvg). All projections and per-player stats on the site come from this CSV — the older xlsx files are retained in `data/` for archival but are not parsed.

- `data/The_Cookie_Cup_players_<YYYYMMDD>_<HHMM>.csv` — weekly snapshot. `parse_stats.py` always picks the most-recently-dated one.
- `data/afl-fantasy-2026.xlsx` (+ 2023/2024/2025 xlsx) — historical / archival only; not consumed by the pipeline.
- `scripts/` — Python pipeline:
  - `parse_stats.py` — reads the latest weekly CSV, writes `docs/data/players.json`.
  - `probe_keeperfantasy.py` — diagnostic; dumps HTML + extracted Stimulus/React data blobs to `scripts/.cache/probe/` (kept for future schema changes).
  - `fetch_rosters.py` — scrapes the 14-team keeperfantasy league into `docs/data/rosters.json`. Reads each team page `/afl/<league>/<1..14>`, extracts the `data-lineup-lineup-value` Stimulus JSON, resolves each player against `players.json` by name + AFL team (with nickname fuzzy matching: Brad↔Bradley, Ollie↔Oliver, Matty↔Matt, Lachie↔Lachlan, etc.). Also reads `/matchup` for the AFL team id→abbr map and the league's scoring formula.
  - `config.json` (gitignored) — `{ "league_id", "team_url_hint" }`.
  - `cookie.txt` (gitignored) — raw `Cookie` request-header value. Get it from DevTools → Network → any keeperfantasy request → Request Headers → Cookie.
- `docs/` — static SPA (vanilla JS, no build step). Deployed via GitHub Pages from `main`/`/docs` to https://sampsonml.github.io/cookie-cup-projector/.
  - `index.html`, `styles.css`, `app.js`
  - `data/players.json`, `data/rosters.json` (both generated by the pipeline).
- `analysis.py`, `draft_analysis.py`, `plots/` — pre-existing exploratory analysis; gitignored.

### Run

Weekly refresh:
```bash
python3 scripts/parse_stats.py && python3 scripts/fetch_rosters.py
```

Initial setup:
```bash
pip install -r requirements.txt
cp scripts/config.example.json scripts/config.json
# then paste raw Cookie header value into scripts/cookie.txt (one line, no quoting)
python3 -m http.server 8765 --directory docs    # local preview
```

### rosters.json shape

Produced by `fetch_rosters.py`. Each team entry:

```json
{
  "id": "14",
  "name": "Naughty Dog Entertainment",
  "formation": { "starters": [...], "emgs": [...], "bonus": [...] },
  "roster": [
    {
      "kf_id": 523, "name": "Bailey Dale", "team_afl": "WBD",
      "positions": ["DEF"], "selected_pos": "DEF",
      "type": "starter", "starting": true,
      "playing_status": 1, "injured": false, "injury_desc": null,
      "cd_id": "CD_I...", "match_quality": "ok"
    }
  ]
}
```

Top-level keys include `has_captains`, `scoring_formula`, `round`, `afl_team_map`, `sport_fixtures` (AFL games for the round, with team abbreviations).

### Projection model

In `docs/app.js`, `project(p, mode)` blends the weekly CSV's signals (all in Cookie Cup scoring, i.e. AFL Fantasy Classic):
- `blend` (default): `0.35·L5 + 0.15·L3 + 0.30·avgPts + 0.20·projAvg`, normalized by available signals. avgPts is the 2026 season average; projAvg is keeperfantasy's own per-game projection.
- `l5`: last-5 average only (fallback chain: L5 → L3 → avgPts → projAvg).
- `season`: season average only (avgPts → L5 → projAvg).
- `kf`: keeperfantasy's projAvg only (projAvg → L5 → avgPts).

Team projection = sum of projection for **available** starters (12 per team in this league: 3 DEF + 5 MID + 1 RUC + 3 FWD). A starter is "unavailable" if `injured`, `playing_status !== 1`, or the user manually excluded them. The league has `numCaptains: 0` so no captain bonus is applied.

### Weekly CSV schema

`data/The_Cookie_Cup_players_<date>.csv` — 26 columns: `name, team, position, owner, age, careerGames, seasons, adp, ownedPct, projAvg, avgPts, totalPts, L5, L3, L1, games, TOG%, kicks, handballs, marks, hitouts, tackles, freesFor, freesAgainst, goals, behinds`. The per-game raw stats (kicks/handballs/marks/etc.) are season averages and can be used to recompute scores under alternative scoring formulas. `owner` is the keeper league team that currently rosters the player.
